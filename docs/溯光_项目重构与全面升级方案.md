## 0. 执行摘要

溯光 TracingLight 当前已实现「AI 出题 → 作业发布 → AI 批改 → 错题归档 → 学习规划」的完整教学闭环，功能面已具备演示与答辩条件。但工程化与架构层存在明显短板：**AI 能力硬编码、数据层单机、主观题批改无人工兜底、缺乏测试与持续集成**。

本方案提出 **「演进式重构（Strangler Fig）+ 人机协同闭环 + AI 能力中台」** 三条主线：

1. **渐进替换而非推倒重来** —— 保住现有可用的业务功能，按模块逐步抽离，降低单人/小团队的重构风险；
2. **主观题引入「AI 初判 → 教师复查 → 结果确认」三级闭环** —— 补齐业务质量最后一块短板，使 AI 批改从"能出结果"升级为"结果可信"；
3. **建设 AI 能力中台** —— 统一多模型接入、Prompt 版本化、评测与降级，为后续自适应学习、智能推荐、多模态出题等创新点铺路。

## 1. 现有问题分析与重构目标

### 1.1 现状盘点

| 层级 | 现状 |
|------|------|
| 前端 | Next.js 16 (App Router) + React 19 + shadcn/ui + Tailwind 4 + ECharts |
| 后端 | Next.js API Routes + 自定义 HTTP 服务（端口 5000，tsup 构建） |
| 数据 | SQLite（sql.js 内存库）+ Drizzle ORM，23 张表 |
| AI | 智谱 GLM-4-Flash 直连 HTTP，Prompt 硬编码于 `src/lib/ai/prompts/*` |
| 认证 | 自建 JWT |
| 工程化 | 无测试、无 CI/CD、无容器化、无监控 |

### 1.2 问题清单（按严重度分级）

**架构层（P0）**

- **单体耦合**：业务逻辑、AI 调用、数据访问散落在 API 路由与组件中，无清晰分层，改一处牵动全局；
- **AI 能力脆弱**：模型直连、无重试/降级/超时控制，Prompt 无版本管理，输出解析靠正则兜底（`invokeStructured`），稳定性差。

**数据层（P0）**

- **SQLite + sql.js 内存库**：数据加载进内存，并发写不安全，重启即需重建，无法支撑真实多用户生产；
- **无备份与迁移机制**：单文件裸奔，数据安全风险高。

**业务闭环层（P0）**

- **主观题批改无人工兜底**：AI 评分直接落库，无教师复查环节，无法保证评分质量，也无法应对学生申诉。

**工程化层（P1）**

- 无单元/集成/E2E 测试，重构无安全网；无 CI/CD，发布靠手动；无日志聚合与监控告警。

**能力层（P2）**

- 单一模型、无 RAG、无知识底座、无自适应与推荐能力，创新空间受限。

### 1.3 重构目标

| 目标 | 说明 | 衡量标准 |
|------|------|----------|
| **可扩展** | AI 能力插件化、领域模块化、多模型可插拔 | 新增一个 AI 能力 ≤ 1 天 |
| **可维护** | 清晰分层 + 领域模型 + 测试覆盖 | 核心模块单测覆盖率 ≥ 70% |
| **业务可信** | 主观题人机协同闭环 | 主观题 100% 经教师确认后落库 |
| **能力升级** | 多模型、RAG、自适应、推荐 | 上线后学情/推荐能力可量化提升 |

## 2. 系统整体架构与模块划分

### 2.1 分层架构（六层）

```
┌─────────────────────────────────────────────────────────────┐
│  表现层 Presentation        Next.js App Router + shadcn/ui     │
├─────────────────────────────────────────────────────────────┤
│  接口层 API / BFF            REST + SSE 流式、统一鉴权、限流      │
├─────────────────────────────────────────────────────────────┤
│  应用服务层 Application      用例编排、事务边界、领域事件发布        │
├─────────────────────────────────────────────────────────────┤
│  领域层 Domain              核心业务规则、聚合根、值对象           │
├─────────────────────────────────────────────────────────────┤
│  AI 能力中台 AI Platform     LLM Gateway / Agent / Prompt / 评测  │
├─────────────────────────────────────────────────────────────┤
│  基础设施层 Infra            PostgreSQL / Redis / 向量库 / 对象存储 │
└─────────────────────────────────────────────────────────────┘
```

**关键原则**：领域层不依赖 AI 与基础设施（依赖倒置）；AI 能力通过统一接口 `AIService` 接入，具体模型可替换。

### 2.2 模块划分（Bounded Context，11 个）

| # | 模块 | 职责 | 依赖 |
|---|------|------|------|
| 1 | 身份与权限 `auth` | 登录、JWT/第三方登录、RBAC | — |
| 2 | 用户与组织 `org` | 学校/学院/专业/班级/教师/学生 | auth |
| 3 | 课程与知识 `curriculum` | 课程、知识点、知识图谱 | org |
| 4 | 题库与出题 `question` | 题库 CRUD、AI 出题、质检入库 | curriculum, AI |
| 5 | 作业与提交 `assignment` | 作业发布、作答、提交 | question, org |
| 6 | 批改与评分 `grading` | 客观题规则引擎 + 主观题 AI+人工闭环 | assignment, AI |
| 7 | 错题本 `errorbook` | 错题归集、错因、掌握度 | grading, curriculum |
| 8 | 学情分析 `analytics` | 六维能力、趋势、预警 | grading, errorbook |
| 9 | 规划与推荐 `plan` | 学习计划、自适应推荐 | analytics, curriculum |
| 10 | AI 能力中台 `ai-platform` | 模型路由、Prompt、Agent、评测 | — |
| 11 | 通知与消息 `notify` | 站内信、告警 | — |

### 2.3 技术选型演进

| 层级 | 现状 | 建议演进 | 理由 |
|------|------|----------|------|
| 数据库 | SQLite (sql.js) | PostgreSQL（本地 Docker / 生产 Supabase） | 并发、事务、备份、pgvector |
| ORM | Drizzle | 保留 Drizzle（迁移平滑） | 类型安全、迁移工具成熟 |
| AI | 智谱直连 | LLM Gateway（Vercel AI SDK / LangChain） | 多模型、流式、降级、成本 |
| 缓存/队列 | 无 | Redis + BullMQ | 批量批改异步化、会话缓存 |
| 向量库 | 无 | pgvector / Milvus | RAG 知识库 |
| 可观测 | 无 | Pino + Sentry + 指标 | 日志、错误、性能追踪 |

> 演进原则：**先用 Docker Compose 本地起 PostgreSQL 对齐 Drizzle schema，再逐步替换数据访问层**，避免一次性重写。

## 3. 各核心功能重新设计与职责边界

### 3.1 AI 出题

- **职责**：根据知识点、难度、题型、数量生成题目，并保证「知识点对齐 + 去重 + 质量」。
- **设计要点**：
  - 出题走独立 `QuestionGenerator` 服务，输入为标准 `QuestionSpec`（知识点 ID、难度、题型、题量、约束）；
  - **多模态**：支持文本题、图文题、公式题（LaTeX）、编程题（含测试用例）；
  - **质检流水线**：生成 → 结构化校验（zod schema）→ 去重（向量相似度）→ 答案自检（反解验证）→ 入库；
  - **边界**：出题模块只负责"生产题目"，不负责"布置作业"，题目入库后由 `assignment` 模块引用。

### 3.2 AI 批改

- **职责**：客观题自动判分 + 主观题 AI 初判（四维评分），输出结构化评分与评语。
- **设计要点**：
  - **客观题**：纯规则引擎，毫秒级、零成本、结果确定；
  - **主观题**：LLM 输出 `{准确性, 逻辑性, 表达性, 拓展性, 总分, 评语, 置信度}`，低置信度（<阈值）强制转人工；
  - **流式**：保留 SSE 流式批改体验；
  - **边界**：批改模块只产出"评分建议"，**最终结果以教师确认为准**（见第 4 节），绝不直接覆盖学生成绩。

### 3.3 AI 解析

- **职责**：错因分析 + 知识点关联 + 学习建议，是错题本与学情分析的知识输入。
- **设计要点**：
  - 错因分类（概念混淆/计算错误/逻辑错误/知识缺失/粗心大意）由 LLM 判断 + 规则兜底；
  - 结合知识图谱定位"前置知识点"，给出溯源式讲解；
  - **RAG 增强**：从教材/讲义向量库检索对应讲解片段，降低幻觉，附可溯源引用；
  - **边界**：解析模块只产出"诊断"，不直接修改错题掌握度（由 `errorbook` 模块消费）。

### 3.4 AI 学习规划

- **职责**：基于学情 + 课表 + 遗忘曲线，生成个性化周计划。
- **设计要点**：
  - 输入：能力雷达、薄弱知识点、可用时段（课表）、考试安排；
  - 输出：按天排布的学习任务（知识点 → 练习 → 复习），支持艾宾浩斯遗忘曲线重排；
  - **边界**：规划模块只"建议"，不强制；学生可调整，调整反馈回推荐模型。

### 3.5 错题本

- **职责**：自动归集错题、错因标签、掌握度追踪、举一反三。
- **设计要点**：
  - 从批改结果自动归集（主观题须在教师确认后归集，避免"误归错题"）；
  - 掌握度 = f(错因类型、复练次数、最近对错、时间衰减)；
  - **举一反三**：按知识点 + 错因推荐同类变式题，复练通过后标记"已攻克"；
  - **边界**：错题本是"数据汇聚 + 追踪"，不产生评分（评分归 grading）。

### 3.6 职责边界矩阵

| 能力 | 出题 question | 批改 grading | 解析 analysis | 规划 plan | 错题本 errorbook |
|------|:---:|:---:|:---:|:---:|:---:|
| 生产题目 | ✅ | — | — | — | — |
| 产出评分建议 | — | ✅ | — | — | — |
| 错因诊断 | — | — | ✅ | — | — |
| 归集与掌握度 | — | — | — | — | ✅ |
| 生成学习计划 | — | — | — | ✅ | — |

## 4. 主观题批改「AI初判—教师复查—结果确认」闭环

### 4.1 状态机

```
待批改(pending) → AI初判中(ai_grading) → AI初判完成(await_review)
   → 教师复查中(reviewing) → 已确认(confirmed)
                           ↘ 已驳回(rejected) → 重新AI批改 → ai_grading
已确认(confirmed) → 学生申诉(appealed) → 二次复查(re_reviewing) → 终审确认(final)
```

### 4.2 流程时序

1. **提交触发**：学生提交主观题 → 作业进入 `pending`；
2. **AI 初判**：LLM 生成四维评分 + 评语 + **置信度**；低置信度自动置顶教师待办；
3. **教师复查**：教师查看 AI 初判，可「采纳 / 修改评分 / 驳回重判」；每次操作留痕（`review_record`）；
4. **结果确认**：确认后**才**落库生效，触发下游（学情更新 + 错题归集 + 学生通知）；
5. **申诉兜底**：学生对已确认结果可申诉，进入二次复查，教师终审后 `final` 锁定。

### 4.3 关键设计

- **置信度分级**：≥0.85 低优先级复核；0.6~0.85 常规复核；<0.6 强制人工（不展示 AI 分数给教师，避免锚定偏差）；
- **留痕审计**：每次 AI 判分与教师修改均记录版本，可回溯「AI 判了多少分、教师改成多少分、为什么」；
- **效率工具**：批量复核面板（同类作答聚类）、教师快捷键（一键采纳/批量通过）；
- **反哺**：教师的修正作为标注样本回流，用于后续 Prompt 优化与模型微调评估。

## 5. 数据模型与错题本数据结构

### 5.1 核心领域模型（ER 概览）

```
user ─┬─ teacher ─┬─ course ─┬─ knowledge_point
      │           │          └─ question (题库)
      │           └─ assignment ── answer ── grading ── review_record
      │                                         │
      └─ student ── error_book ── knowledge_point (错因关联)
                   └─ study_plan ── study_session
```

### 5.2 错题本表结构设计

```sql
-- 错题主表
CREATE TABLE error_book (
  id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  student_id      UUID NOT NULL REFERENCES "user"(id),
  question_id     UUID NOT NULL REFERENCES question(id),
  source_grading  UUID REFERENCES grading(id),      -- 来源批改（可空，手动录入）
  error_type      TEXT NOT NULL,                     -- 概念混淆/计算错误/逻辑错误/知识缺失/粗心大意
  error_analysis  TEXT,                              -- AI 解析原文
  knowledge_ids   UUID[],                            -- 关联知识点（数组，便于图谱）
  mastery_rate    NUMERIC(5,2) DEFAULT 0,            -- 当前掌握度 0~100
  review_count    INT DEFAULT 0,                     -- 复练次数
  last_result     BOOLEAN,                           -- 最近一次复练对/错
  status          TEXT DEFAULT 'open',               -- open / reviewing / conquered
  conquered_at    TIMESTAMPTZ,
  created_at      TIMESTAMPTZ DEFAULT now(),
  updated_at      TIMESTAMPTZ DEFAULT now()
);

-- 复练记录（举一反三追踪）
CREATE TABLE error_review (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  error_book_id UUID NOT NULL REFERENCES error_book(id),
  question_id   UUID NOT NULL REFERENCES question(id), -- 复练用的变式题
  correct       BOOLEAN,
  answered_at   TIMESTAMPTZ DEFAULT now()
);

-- 批改复查记录（人机闭环留痕）
CREATE TABLE review_record (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  grading_id    UUID NOT NULL REFERENCES grading(id),
  reviewer_id   UUID NOT NULL REFERENCES "user"(id),
  action        TEXT NOT NULL,                        -- accept / modify / reject / appeal / final
  ai_score      JSONB,                                -- AI 初判快照
  final_score   JSONB,                                -- 教师最终评分
  comment       TEXT,
  created_at    TIMESTAMPTZ DEFAULT now()
);
```

### 5.3 设计要点

- **掌握度公式**：`mastery = α·历史掌握 + β·最近对错 + γ·时间衰减`，参数可调；
- **索引**：`(student_id, status)`、`(student_id, knowledge_ids)`、`(student_id, error_type)`；
- **扩展**：`knowledge_ids` 用数组便于知识图谱聚合，若查询复杂可拆关联表 + GIN 索引；
- **软删除**：错题采用 `status` 流转而非物理删除，保留学习轨迹。

## 6. 全面升级与创新点

### 6.1 自适应学习（Adaptive Learning）

- 基于 **IRT（项目反应理论）** 或贝叶斯知识追踪（BKT）估计学生能力值 `θ` 与知识点掌握概率；
- 根据 `θ` 动态调难度：能力强 → 拔高题，能力弱 → 巩固题，实现"千人千题"。

### 6.2 智能推荐

- **协同过滤**：相似学生画像（分层、能力雷达）的错题/练习推荐；
- **知识图谱路径推荐**：从薄弱知识点沿"前置→后继"路径规划补救序列；
- **混合排序**：融合掌握度、遗忘曲线、考试临近度做推荐打分。

### 6.3 学情分析（Learning Analytics）

- 六维能力雷达 + 知识热力图 + 成绩趋势 + **异常预警**（成绩骤降、连续未提交）；
- 教师端"班级画像"：分层分布、共性薄弱点、教学建议；
- 学生端"个人画像"：能力变化曲线、与班级均值对比。

### 6.4 多模态出题

- 文本题、图文题、公式题（LaTeX 渲染）、编程题（含测试用例自动判题）；
- 图片理解（题目含图/图表），视频讲解题（可选）。

### 6.5 RAG 知识底座

- 将教材、讲义、课件向量化入 pgvector；
- AI 解析/讲解时检索权威片段，**附可溯源引用**，显著降低幻觉，提升教育可信度。

### 6.6 多智能体编排（Agent）

- 出题 Agent、批改 Agent、解析 Agent、规划 Agent 各司其职，通过编排层协作；
- 未来可接入更多模型（通义/豆包/DeepSeek/OpenAI 兼容）做能力路由与成本优化。

## 7. 分阶段实施步骤与里程碑

### Phase 0 — 工程地基（第 1~2 周）

- **目标**：为重构建立安全网，不新增业务功能。
- **任务**：Git 托管 + GitHub Actions CI；Docker 起 PostgreSQL；Drizzle 迁移对齐；核心模块首批单测；日志 + Sentry。
- **里程碑 M0**：`CI 全绿 + 数据可从 SQLite 完整迁移到 PG`。

### Phase 1 — AI 能力中台（第 3~5 周）

- **目标**：抽离 AI 硬编码，统一接入与评测。
- **任务**：LLM Gateway（多模型 + 重试/降级/流式）；Prompt 模板化 + 版本管理；结构化输出用 zod schema 强校验；建立 Prompt 评测集（黄金标准题）。
- **里程碑 M1**：`AI 能力中台上线，模型可热切换，Prompt 变更可回滚`。

### Phase 2 — 主观题人机闭环（第 6~8 周）

- **目标**：补齐业务质量闭环。
- **任务**：批改状态机 + 教师复查面板 + 留痕审计 + 申诉流程；批量复核聚类工具。
- **里程碑 M2**：`主观题 100% 经教师确认后落库，复查留痕可回溯`。

### Phase 3 — 学情分析与推荐（第 9~12 周）

- **目标**：从"记录数据"到"洞察与建议"。
- **任务**：学情看板升级（预警 + 班级画像）；错题掌握度建模；协同过滤 + 图谱推荐；学习规划自适应重排。
- **里程碑 M3**：`推荐与自适应上线，学习计划支持遗忘曲线重排`。

### Phase 4 — 多模态与 RAG（第 13~16 周）

- **目标**：能力创新与可信度跃升。
- **任务**：多模态出题；教材向量化 + RAG 解析；多智能体编排接入；成本与效果监控看板。
- **里程碑 M4**：`多模态出题 + RAG 解析落地，AI 回答附可溯源引用`。

---

## 附：风险与建议

- **过度设计风险**：单人/小团队应坚持"演进式重构"，每阶段产出可运行的增量，避免长期无交付的"大重写"；
- **数据迁移风险**：SQLite → PG 迁移需做数据一致性校验脚本与回滚预案，迁移期间双写或只读保护；
- **AI 质量风险**：AI 评分/解析必须保留人工兜底与置信度机制，教育场景"可信"优先于"自动化"。
