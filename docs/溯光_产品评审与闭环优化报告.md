> 评审日期：2026-09-04　|　视角：产品评审 × 功能测试双重视角
> 方法：13 组 API 实测（含 5 项 AI 能力真实调用）+ 全部 32 个前端页面代码级交互审查 + 模块衔接关系梳理

## 二、问题清单（按严重程度排序）

### 🔴 高：闭环关键节点断裂（5 项）

#### P1-1 批改完成后不通知学生——闭环最关键的断点
- **现状**：通知只在「教师发布作业」时发送；教师批改完成（批量批改/覆盖改分）后，学生**不知道成绩已出**，只能反复刷作业列表。
- **影响**：「作答→批改→查看解析」这条最高频的链路被硬性中断；教师批改的价值延迟甚至归零。
- **建议**：批改落库成功后向该学生发送通知（`title: 作业《X》已批改`，`link: /student/assignments/<id>`），通知中心已支持 link 跳转，纯增量改动约 20 行。

#### P1-2 错题本缺「针对性练习」出口——AI 解析的价值没有落地
- **现状**：AI 解析返回 `similar_questions`（纯文本）+「举一反三」，仅作展示；错题卡片上没有「针对此错题生成练习」的按钮。学生看完解析后无事可做，回到原点。
- **影响**：「错题归档→解析→巩固练习」链路断裂，错题本退化成"电子错题抄本"。这是整个学习闭环**价值密度最高却完全缺失**的一环。
- **建议**：错题卡片新增「举一反三 · 即时练习」按钮 → 调 `generate-questions`（同知识点、同题型、错题型优先）生成 3 题 → 弹层即时作答 → 客观题即时判分 → 结果回写掌握度；答对可引导「标记为已掌握」。

#### P1-3 学生作业详情页无「去错题本」出口
- **现状**：已批改且失分的作业详情页展示了得分与错题解析，但没有任何跳转错题本的 CTA（grep 全页无 errors 跳转）。
- **建议**：非满分的已批改作业，页顶显示「本次错题已归档 → 去错题本复习」横幅（带未处理错题数）。

#### P1-4 AI 答疑是孤儿页——最好的功能学生发现不了
- **现状**：`/student/assistant` 功能完整（会话持久化、多轮上下文、600 字实测回复），但学生端侧边栏与移动 TabBar **均无入口**（layout 中 grep "assistant" = 0）。
- **影响**：全平台最直观的 AI 价值点对用户不可见。
- **建议**：学生端导航加「AI 答疑」（icon: MessageCircleQuestion），移动端 TabBar 收录。

#### P1-5 教师端 3 个孤儿页——考试与公告功能不可达
- **现状**：`/teacher/exams`（考试管理）、`/teacher/announcements`（公告）、`/teacher/courses/[id]`（课程详情）功能可用但导航无入口，教师只能手敲 URL。
- **建议**：教师端导航补「考试管理」「公告」两项；或按"使用便捷优先"原则，考试并入作业管理页签、公告并入课程详情。

### 🟡 中：体验与衔接问题（6 项）

#### P2-1 教师学情看板"只能看不能做"
- **现状**：看板能定位薄弱学生（下钻详情）、能看到知识点掌握热力图，但没有任何行动出口——不能从"发现薄弱"直接"布置针对作业"或"发督促通知"。
- **建议**：热力图薄弱知识点点击 → 弹出快捷流「AI 出题 → 选择薄弱学生 → 一键布置」（复用现有 ai-generate + assignments POST，纯前端编排）。

#### P2-2 知识图谱无行动出口
- **现状**：图谱按掌握度着色（红/黄/绿）很直观，但点击薄弱节点后无事可做（无跳规划/错题/练习/答疑）。
- **建议**：叶子节点点击 → 弹层展示掌握度明细 + 三个按钮：「去错题本（该知识点）」「加入学习规划」「问 AI 老师」。

#### P2-3 课程详情页语义断层
- **现状**：`student/courses/[id]` 仅 6 行——redirect 到学情页。学生从课程卡片进入预期"学习这门课"（材料/作业/答疑），实际落在学情看板。
- **建议**：两选一：① 重建真正的课程聚合页（本课材料+作业+图谱+答疑四个入口，成本约半天）；② 短期把首页卡片文案改为「查看学情」消除误导。

#### P2-4 学习规划"复习"项跳转错位
- **现状**：规划会话 `review` 类型跳知识图谱、`practice` 跳错题本——复习环节去看图谱，逻辑欠妥（图谱是诊断工具不是复习材料）。
- **建议**：review → 跳错题本（待复习 tab）；图谱放给 `diagnose` 类型（可新增）。

#### P2-5 20 处原生 alert 与整体 UI 风格割裂
- **现状**：教师端/学生端仍有 20 处 `alert()`（如 AI 出题校验、作业发布提示），与平台现代化 UI 不符。
- **建议**：统一替换为 toast（项目已有 toast 体系），一次性批量替换约 1 小时。

#### P2-6 AI 出题"生成即入库"，无预览编辑
- **现状**：AI 生成的题目直接写题库，教师不能在入库前审校（AI 偶发的错误答案/解析会直接进题库，可能被布置给学生）。
- **建议**：生成后先展示预览卡片，教师可编辑/剔除，确认后才入库（需要把 generate-questions 的"生成"与"入库"拆成两步）。

### 🟢 低：打磨项（4 项）

| # | 问题 | 建议 |
|---|---|---|
| P3-1 | 错题无间隔复习机制：mastered 后不再出现，pending 无到期提醒 | 增加 `next_review_at` 字段，按 1/3/7 天间隔提醒（通知场景现成） |
| P3-2 | `grade-stream` 流式批改仍不落库 | 前端实际未使用该接口，标注废弃或补落库 |
| P3-3 | 通知铃铛无批量已读、无类型筛选 | 补批量已读按钮 |
| P3-4 | 移动端 tab 高亮失效、管理端移动导航缺失（历史遗留） | 维持原修复建议 |

## 三、闭环衔接关系梳理

### 目标闭环：出题 → 布置 → 作答 → 批改 → 解析 → 错题归档 → 图谱诊断 → 个性化规划 → 针对性练习

| 环节 | 现状 | 断点 |
|---|---|---|
| 1. AI 出题 → 入题库 | ✅ 通（生成即入库，出题页可跳题库） | P2-6 无预览审校 |
| 2. 题库 → 布置作业 | ✅ 通（布置页可选题/含 AI 出题面板） | — |
| 3. 布置 → 学生感知 | ✅ 通（发布作业发通知） | — |
| 4. 作答 → 批改 | ✅ 通（统一管线已修复） | — |
| **5. 批改 → 学生感知** | ❌ **断** | **P1-1 无批改通知** |
| 6. 批改 → 解析展示 | ✅ 通（作业详情内嵌解析） | — |
| **7. 解析/详情 → 错题本** | ❌ **断** | **P1-3 无跳转出口** |
| 8. 错题本 → AI 解析 | ✅ 通（解析/举一反三展示） | — |
| **9. 解析 → 针对性练习** | ❌ **断** | **P1-2 举一反三不可练** |
| 10. 错题/掌握度 → 图谱诊断 | ✅ 通（masteryLog 驱动着色） | — |
| **11. 图谱诊断 → 行动** | ❌ **断** | **P2-2 无出口** |
| 12. 诊断 → 个性化规划 | ✅ 通（规划生成引用薄弱点） | — |
| 13. 规划 → 针对性练习 | ⚠️ 半通 | **P2-4 review 跳转错位；练习落地靠跳错题本** |
| 14. 教师侧：诊断 → 行动 | ❌ 断 | **P2-1 看板无布置/通知出口** |

**结论：9 个环节里 5 个不通或半通，且全部是"最后一公里"类的 UI 级断点——后端数据与 API 全部就绪，打通成本远低于开发新功能。**

## 四、缺失功能评估（以使用便捷为最高优先级）

| 优先级 | 缺失功能 | 理由 | 落地方式 |
|---|---|---|---|
| ★★★ | **举一反三即时练习** | 闭环第 9 环，错题本价值的放大器；数据链路（generate-questions + submit + 掌握度）全部现成 | 错题卡片按钮 + 弹层作答组件 |
| ★★★ | **批改完成通知** | 闭环第 5 环，最高频链路；通知机制现成 | 批改落库后 insert notification（约 20 行） |
| ★★☆ | **看板一键布置** | 教师"发现问题→采取行动"的关键一步；否则学情看板是只读仪表盘 | 热力图点击 + 快捷布置弹层 |
| ★★☆ | **AI 出题预览审校** | 防止 AI 偶发错误直接进题库并布置给学生（质量闸门） | generate 与入库拆分 + 预览编辑卡片 |
| ★☆☆ | 错题间隔复习提醒 | 错题本从"记录"升级为"复习引擎" | next_review_at + 到期通知 |
| ★☆☆ | 教师评语提醒 | 覆盖改分/评语（override_comment）学生无感知 | 并入批改通知的同一机制 |

**不建议新增**的功能：打卡/积分/排行榜等激励体系（当前阶段用户量不支持其价值，且偏离教学工具定位）；更多 AI 能力（现有 7 项 AI 能力利用率因断点尚未吃满，先打通再扩容）。

## 五、推翻重设计建议

1. **课程详情页（student/courses/[id]）**——现状是 6 行 redirect，属于"有 URL 无功能"。建议推翻为**课程聚合页**：顶部课程横幅，下方四宫格（本课材料 / 本课作业 / 本课图谱 / 问 AI 老师），作为学生端"按课程学习"的主入口。这是学生端信息架构里"课程"与"功能"两套导航的交汇点，价值明确。
2. **grade-stream 流式批改**——前端从未使用、不落库、与统一管线语义重复。建议**废弃**（占位 404），批改体验统一走 batch + 进度反馈（M4），减少维护面。
3. **规划页"复习→图谱"跳转**——语义错位，直接改。

## 六、可落地实施步骤

### 第一批：接通主链路（约 2 小时，全部为低风险增量改动）
1. 批改完成通知（P1-1）：grading.service 落库后 insert notification（含 link）；
2. 导航补全（P1-4/P1-5）：学生端加 AI 答疑，教师端加考试/公告；
3. 作业详情页错题 CTA（P1-3）：非满分已批改作业显示「去错题本」横幅；
4. 规划 review 跳转修正（P2-4）：改为错题本。

### 第二批：补齐练习闭环（约 3 小时）
5. 举一反三即时练习（P1-2）：错题卡片「生成练习」→ 弹层 3 题 → 即时判分 → 回写掌握度；
6. 图谱节点行动出口（P2-2）：节点弹层三按钮；
7. AI 出题预览审校（P2-6）：generate 拆两步。

### 第三批：教师行动力与体验统一（约半天）
8. 看板一键布置（P2-1）：热力图 → AI 出题 → 选学生 → 布置的快捷流；
9. 课程聚合页重设计（P2-3）；
10. alert → toast 批量替换（P2-5）；
11. （可选）错题间隔复习（P3-1）、通知批量已读（P3-3）。

### 每批完成后的验收标准
- 第一批：学生从「提交作业」到「收到批改通知 → 点进详情 → 跳错题本」全程无手动刷新、无死路；
- 第二批：从「一道错题」出发，能在 3 次点击内完成「解析 → 变式练习 → 判分 → 掌握度更新」；
- 第三批：教师从「看板发现薄弱知识点」到「该知识点作业已布置给薄弱学生」≤ 5 次点击。

## 七、总体结论

- **功能完备度：高。** 用户点名的 8 大功能全部真实可用，AI 七项能力（出题/批改/解析/规划/答疑/报告/推荐）实测全部正常，客观题规则引擎数学等价、三角色权限、数据真实性等基础质量经前几轮治理已达标。
- **核心短板：闭环断点。** 学习闭环 14 个衔接点中 5 个断裂，且全部集中在"环节之间的出口/入口"——属于 UI 级增量改动，无一处需要动后端数据模型，**三批共约一个工作日即可全线打通**。
- **产品建议一句话：不要再加新 AI 能力，先把现有能力的"最后一公里"接上——打通后，平台从"功能集合"升级为"学习飞轮"。**
