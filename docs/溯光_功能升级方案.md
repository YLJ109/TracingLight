# 溯光（TracingLight）功能升级方案

> 定位：高校智慧教育 AI 平台 —— 以「AI 自适应教学闭环」为主线，在现有能力之上做真增量，避免重复造轮子。

---

## 一、现状盘点：哪些能力已具备

在规划升级前，先明确项目已拥有的基础，防止方案重复建设：

| 现状能力 | 载体 | 状态 |
|---|---|---|
| 错因类型（概念混淆/计算/逻辑/知识缺失/粗心等） | `recommend` 薄弱分析、`analyze-error` | ✅ 已有 |
| 知识点前置依赖展示 | `recommend` WeakPoint.prerequisites、知识图谱 | ✅ 已有 |
| AI 补习建议 | `recommend` aiSuggestion | ✅ 已有 |
| 学习计划（周/冲刺/日）+ 复习/练习/预习 session | `studyPlan`、`studySession` | ✅ 已有 |
| 学习反馈信号（too_easy/just_right/too_hard/skip） | `studySession.student_feedback` | ✅ 已有 |
| 错题复习记录 | `reviewRecord` | ✅ 已有 |
| AI 出题 / 批改 / 答疑 / 学情报告 / 画像 / OCR | `ai/*` 系列 API | ✅ 已有 |
| 激励体系表（积分/签到/商城/兑换/装饰） | `points_*`、`sign_in_*`、`shop_item`、`redeem_order` | ✅ 已有表 |

**结论**：学生端「智能推荐」与 AI 单项能力已经丰满，**真正的缺口在「串联成每日闭环」和「教师/管理端的数据聚合呈现」**，以及「更主动的诊断-行动」闭环。

---

## 二、升级主线

> 把分散的数据与 AI 能力串成一条持续自愈的链：
> **学生每题练习 → AI 归因错因并排期复习 → 每日"今日任务"闭环 → 教师聚合共性问题 → 管理端大屏呈现整体学情**

三个板块对应三级角色，共享同一数据底座（`knowledge_mastery_log` / `error_book` / `review_record` / `study_session`）。

---

## 三、板块一：自适应复习引擎（学生端）

### 3.1 目标
把「错题本、薄弱点、学习计划」三个入口整合为一个 **每天打开就要做的「今日任务」**，由 AI 按遗忘曲线与个人弱点自动排期，做到「今日只做最该做的事」。

### 3.2 设计（分两步实现）

#### 3.2.1 今日任务聚合（轻量、前端+聚合 API 实现）
- 新建只读聚合 API `GET /api/student/today`，一次性返回：
  - 已到期需复习的错题（基于 `error_book` 下次复习时间 ≤ 今天）
  - 薄弱知识点（`mastery < 60`）的练习任务
  - 今日 `study_session`（复习/练习/预习）
  - 一次性把「知识图谱」里该知识点建议的前置依赖标出
- 学生端新增「今日任务」页（或把 `recommend`/`overview` 改造为首屏），卡片式任务清单，含「错因标签 + 前置依赖 + 预计时长」。
- 完成一项即回写 `review_record` / `study_session.is_completed`，闭环打勾。

#### 3.2.2 AI 排期与班主任（进阶，模型编排）
- 新增「随时来教」逻辑：用户完成后点「太简单/刚好/太难」反馈，AI 据此动态下轮排期（下轮间隔 = f(反馈 + 掌握度)，SM-2 遗忘曲线变体）。
- AI 错因归因扩展到「知识断层」：当一个知识点的前置知识点掌握度也低时，AI 明确提示「先补 xxx 再学本点」，并可一键生成针对性练习（复用 `practice/generate`）。

### 3.3 新增/改动
- 新增 API：`/api/student/today`（聚合只读）、`/api/student/task/*`（完成/反馈回写）。
- 新增/改造页面：`/student/today`（今日任务），或改造 `recommend` 首屏。
- 数据：复用 `error_book`/`review_record`/`study_session`，**基本无需新表**（如需记录排期参数可给 `review_record` 增 `next_review_at`/`interval` 字段）。

## 四、板块二：教师端 AI 自动化

### 4.1 目标
把老师从「翻 40 份作业找共性」的重复劳动中解放出来，AI 主动给出可行动的结论。

### 4.2 功能清单

#### 4.2.1 共性问题清单（本期重点）
- 新 API `GET /api/teacher/analytics/common-issues?assignment_id=..`：聚合全班成绩 + 错题 + 知识点掌握度，AI 汇总输出：
  - 「全班暴露的 TopN 共性薄弱知识点」
  - 「共性问题所在题目/题型 + 典型错因」
  - 附带「建议下一步：专项练习 / 课堂回顾某知识点」一句话行动
- 教师端「学情分析/作业详情」新增「共性问题」卡片展示。

#### 4.2.2 临界生预警
- 从行为 + 成绩 + 掌握度数据中识别「临界生」（持续下滑 / 掌握度低但积极参与 / 最近表现骤降），AI 生成关注名单 + 每个学生一句诊断。
- 教师端「学生列表」新增「需关注」角标与名单筛选。

#### 4.2.3 学情周报批量生成（进阶）
- 按「课程/班级 + 时间范围」一键生成学情周报（掌握度变化、作业完成、共性问题、进步学生 TopK、建议），可导出。

### 4.3 新增/改动
- 新增 API：`common-issues`、`at-risk-students`、（进阶）`weekly-report`。
- 改造页面：`/teacher/analytics`、`/teacher/assignments/[id]`、`/teacher/students`。
- 数据：复用现有成绩/错题/掌握度/行为日志，**无需新表**。

## 五、板块三：教务数据大屏（管理端）

### 5.1 目标
一张大屏承载「学校整体学情」实时视图，用于演示、答辩与教务决策。

### 5.2 内容设计
- 顶层指标卡：注册数、今日活跃、作业完成率、平均掌握度、签到人数。
- 图表区（复用现有 `admin/analytics` + 大屏化）：
  - 全知识点掌握度分布（热力/分布）
  - 各课程完成率 / 掌握度横向对比
  - 签到热力图（按班级/时间）
  - 活跃趋势
- 大屏模式（全屏隐藏侧栏）、自动刷新、可切换「教务/教师」视角。

### 5.3 新增/改动
- 新页面：`/admin/dashboard`（大屏）。
- 聚合 API：在既有 `admin/overview`、`analytics` 基础上补充实时/大屏聚合字段。
- 数据：复用现有表，**无需新表**。

## 六、创新点提炼（区别于普通教务系统）

1. **错因驱动的动态排期** —— 不止「错题重做」，而是「按错因 + 遗忘反馈排下一次复习」，构成个性化复习引擎。
2. **前置知识断层提示** —— 薄弱点上溯前置依赖，明确「先补哪、再学哪」，形成路径而非孤立清单。
3. **教师端共性问题自动汇总 + 行动建议** —— 老师直接得到「该讲什么」，而非原始统计。
4. **临界生预警** —— AI 从数据主动圈出需老师拉一把的学生。
5. **三级数据闭环** —— 学生练习、教师批改、管理看板共享同一学情底座，避免数据孤岛。

## 七、技术实现要点

- **架构**：沿用现有 Next.js App Router + better-sqlite3 + Drizzle；AI 走 `src/lib/ai/client.ts`（智谱 GLM-4-Flash）统一接入，错误配置已隔离。
- **模型编排**：新增 `src/lib/ai/adaptive.ts`（排期/归因）、`src/lib/ai/teacher.ts`（共性/临界生）。所有 AI 调用遵循现有 `AIConfigError` 占位符校验，避免无效 Key 崩溃。
- **数据**：绝大多数复用现有表；仅自适应排期可能给 `review_record` 增字段。
- **前端**：复用现有布局/组件库（Tailwind + ECharts + 渐变卡片风格），新页面沿用 `SetActiveNav` 侧栏高亮机制。
- **测试**：新增针对性单测 + Playwright E2E（今日任务勾选、教师共性清单渲染、大屏数据加载）。

| 阶段 | 交付物 | 价值 |
|---|---|---|
| **P1 自适应复习引擎** | 今日任务聚合页 + 错因/前置排期 + 反馈闭环 | 学生端闭环核心，可演示 |
| **P2 教师端自动化** | 共性问题清单 + 临界生预警 | 教师提效，演示直观 |

## 九、风险与注意

- **功能已较多**：新增功能需克制，优先做「串关系」而非「添菜单」，避免信息过载。
- **AI 依赖**：无有效 API Key 时新功能应有降级（读本地数据展示，不打 AI）。
- **数据量**：TODO 聚合查询需加索引，避免多表扫慢（`error_book`/`study_session` 建议补 `(student_id, date)` 索引）。
- **一致性**：教师/管理端聚合与现有 analytics 口径保持一致，避免数据打架。
