## 一、方案总览与技术选型

### 1.1 项目定位与部署形态

溯光 TracingLight 面向高校师生，核心闭环：**教师发布作业 → 学生在线作答提交 → AI 初判 + 教师复核 → 成绩发布 + 错题归集 → 学情分析 → 个性化推荐**。

**部署定位：以本地演示为主（答辩场景），生产演进预留。**

### 1.2 技术选型：SQLite 落地 + PostgreSQL 演进预留

| 项目 | 最终选型 | 理由 |
|------|----------|------|
| 数据库（落地） | **SQLite + better-sqlite3** | 本地演示零环境依赖，双击即跑，答辩现场最稳；better-sqlite3 解决 sql.js 的持久化与并发隐患 |
| 数据库（演进） | **PostgreSQL + pgvector** | 生产多实例/JSONB/向量检索；Drizzle 已抽象方言，演进迁移成本可控 |
| ORM | Drizzle ORM（保留） | 类型安全 + 迁移工具，换库只改连接层 |
| 前端 | Next.js 16 + React 19 + shadcn/ui + Tailwind 4 | 现状保留 |
| AI | 智谱 GLM-4-Flash（可换多模型） | 现状保留，走 AI 能力中台 |

**为什么"本地演示"选 SQLite：**
1. 答辩现场**零环境风险**——不依赖 Docker、网络、云服务，双击 bat 就跑，避免 Windows 下 Docker/WSL2 的翻车点；
2. 单文件数据库，演示数据随项目走，备份=复制文件；
3. 性能对本地单用户/演示账号完全够用。

**生产演进路线（作为技术亮点讲）**：Drizzle 抽象了方言、schema 用 DDL 描述，未来上线多实例时**无缝迁移到 PostgreSQL + pgvector**（JSONB、数组、向量检索、原生并发），无需重写业务代码——这是答辩时展示架构前瞻性的加分项，而非风险。

### 1.3 系统架构（六层 + 11 模块）

```
表现层 → 接口层(API/BFF) → 应用服务层 → 领域层 → AI能力中台 → 数据层(SQLite / PostgreSQL)
```

11 个有界上下文：`auth` / `org` / `curriculum`（课程·知识点·图谱）/ `question` / `assignment` / `grading` / `errorbook` / `analytics`（学情·行为）/ `plan`（规划推荐）/ `ai-platform` / `notify`。

### 1.4 核心设计原则

1. **AI 只出建议，人按需终审**：无主观题全自动判分；有主观题默认复核，教师可自定义；
2. **权限最小化**：学生仅见本人数据，教师仅见所授课程；
3. **状态机驱动**：作业、提交、批改均有明确状态流转；
4. **草稿先行**：学生作答实时存草稿；
5. **课程中心**：一切资源以课程为容器组织。

## 二、角色与权限体系

### 2.1 角色定义

| 角色 | 说明 | 典型能力 |
|------|------|----------|
| **教师 teacher** | 课程负责人 | 建课/发布作业/批改/终审成绩/建设图谱/发布材料/看学情 |
| **学生 student** | 选课学习者 | 学习材料/作答提交/查看成绩与批改/错题复习/AI答疑 |
| **管理员 admin** | 平台运营者（平台级） | 组织/用户/课程管理、系统设置、数据监控、日志审计、备份 |

### 2.2 权限矩阵（RBAC）

| 能力 | 教师 | 学生 |
|------|:---:|:---:|
| 发布/编辑作业 | ✅ | — |
| 查看全班提交 | ✅ | 仅本人 |
| 批改 | ✅ | — |
| 成绩终审/发布 | ✅ | — |
| 建设知识/能力/思政图谱 | ✅ | — |
| 发布视频/课件材料 | ✅ | — |
| 提交作业 | — | ✅ |
| AI 答疑 | ✅ | ✅ |

### 2.3 管理员权限与登录设计（三端）

管理员是**平台级超级管理员**，拥有全平台权限（组织/用户/课程/系统设置/日志/备份），且不参与具体教学（不归属任何课程）。管理员权限独立于教学角色，是矩阵之外的「平台管理域」。

**登录页三个 Tab**：学生端 / 教师端 / 管理端。

| 端 | 默认账号 | 说明 |
|----|----------|------|
| 学生端 | `stu_zhang` 等演示账号 | 自动填入 |
| 教师端 | `teacher_wang` 等演示账号 | 自动填入 |
| 管理端 | **`admin` / `123456`** | 自动填入，平台超级管理员 |

## 三、课程中心与作业全生命周期

### 3.1 课程中心导航（核心重构）

一切资源以课程为容器：首页展示「我的课程」卡片列表，点击进入课程详情，再进入各功能模块。

```
教师端首页 = 我的课程(卡片) → 课程详情 → { 题库 / 作业 / 材料 / 图谱 / 学生 / 学情 }
学生端首页 = 我的课程(卡片) → 课程学习页 → { 课件视频 / 作业 / 图谱 / 学情 }
```

- 课程卡片：课程名、学期、班级、学生数、作业数、最近动态、**渐变封面**；
- 课程详情：课程信息 + Tab 导航（教师：概览/题库/作业/材料/图谱/学生/学情；学生：课件视频/作业/图谱/学情）；
- 题库从课程进入，不再是全局入口。

### 3.2 作业发布流程

```
课程详情 → 新建作业(草稿) → 选题组卷(AI出题/题库选) → 设分值/截止/限时/防作弊
   → 设批改方式(review_mode) → 发布 → 通知学生 → 到截止
```

### 3.3 批改方式 review_mode

| review_mode | 触发 | 行为 |
|-------------|------|------|
| `auto` | 无主观题 | 提交后规则引擎自动判分，成绩即时生效 |
| `teacher_review` | 含主观题 | AI 初判 + 教师复核后成绩生效 |

教师可自定义覆盖（含主观题也可强制 auto，或无主观题也可设复核）。字段 `assignment.review_mode` + 冗余 `has_subjective`。

### 3.4 作业提交流程

草稿实时保存（防抖落库）→ 显式提交（二次确认）→ 客观题即时判分 → 主观题入批改队列。支持限时（倒计时+后端校验）、补交（is_late）、重复提交（max_attempts + attempt_no）。

### 3.5 批改流程

```
教师查看提交 → 客观题自动判分 → 主观题 AI 初判(四维+置信度) → 教师复核(采纳/修改/驳回) → 成绩发布
```

客观题自动判分；主观题由教师复核 AI 初判结果（分级复核，见 3.6）；全程留痕（`review_record`），异常驳回重判。

### 3.6 批改与评分机制

- 客观题：规则引擎（多选半对、填空容错）；
- 主观题：四维评分（准确性/逻辑/表达/拓展）+ 置信度，<0.6 强制人工；
- **分级复核**：≥0.85 批量通过（抽查）、0.6~0.85 常规复核、<0.6 强制人工，教师可设抽查比例；
- AI 成本：额度监控 + 降级链路 + 批改队列化 + 缓存复用。

参照学习通、超星。六区块信息架构（顶栏 → 状态横幅 → 作业信息卡 → 题目区 → 进度导航 → 底部操作栏）+ 五状态切换（未开始/进行中/已截止/已提交/已批改）。逐题作答、草稿自动保存、倒计时、提交二次确认、查看批改、申诉入口。

## 五、知识图谱与学习行为分析

### 5.1 三图谱体系

| 图谱 | 节点 | 关系 |
|------|------|------|
| 知识谱图 | 知识点 | 前置/后继/包含 |
| 能力谱图 | 能力点（计算/逻辑/表达/编程） | 能力→知识点（培养映射） |
| 思政谱图 | 思政点（家国情怀/科学精神/职业道德） | 思政→知识点/课程（融入映射） |

三图谱统一可视化组件，`node_type` 区分颜色层级。**图谱构建策略**：AI 辅助生成（从课程大纲抽取）+ 模板预置（预置常见能力点/思政点）+ 教师确认，避免空表。

### 5.2 学习行为与薄弱分析

教师发布的视频/课件，通过 `learning_behavior_log`（停留时长/进度/重看次数）补充「学习投入」评价维度。**注意**：停留时间弱信号，需与作业得分、重看次数三者加权，避免"认真学被误判为薄弱"。

### 5.3 推荐路径图

按课程分类的学习路径图：`薄弱知识点 → 前置补漏 → 巩固练习 → 目标`，复用图谱可视化，颜色标掌握度。

## 六、UI/UX 设计规范

### 6.1 设计语言：粉紫科技教育

定位「溯光 = 追光」的品牌意象，用粉紫渐变营造光感，整体现代、轻盈、有科技教育气质，克制不堆砌。

### 6.2 色彩系统

| Token | 值 | 用途 |
|-------|-----|------|
| `primary` | violet-600 `#7c3aed` | 主色（按钮/链接/激活） |
| `brand-gradient` | violet-500 → fuchsia-500 | 渐变（logo/头像/封面/强调） |
| `sidebar` | violet-950 `#2e1065` | 深紫侧边栏 |
| `background` | `#faf9fd` | 浅紫灰内容区 |
| `accent-pink` | fuchsia/pink | 粉点缀 |
| `accent-teal` | teal-500 | 成功/积极/AI 语义 |
| `success/warning/error` | 绿/琥珀/红 | 状态语义 |

### 6.3 字体 / 间距 / 圆角 / 阴影 / 图标

- 字体：Inter + Noto Sans SC；字号阶梯 12/13/14/15/20/24；
- 间距：4px 基准（4/8/12/16/24/32）；
- 圆角：卡片 12px、按钮 8px、徽标 999px；
- 阴影：克制（卡片悬浮 `0 10px 30px -12px rgba(76,29,149,.18)`）；
- 图标：lucide-react，统一 20px 描边。

### 6.4 布局系统（课程中心）

深紫侧边栏 + 毛玻璃顶部栏（`backdrop-blur`）+ 卡片化内容区 + 渐变封面课程卡片网格。

### 6.5 三个视觉记忆点

1. **渐变封面课程卡片**：每门课一个粉紫色调封面，第一眼有质感；
2. **数据可视化统一色板**：ECharts 统一用紫+青绿+琥珀+粉四色，雷达/热力/趋势图风格一致；
3. **玻璃拟态登录页**：粉紫渐变背景 + 毛玻璃卡片，答辩第一屏惊艳。

### 6.6 组件状态与动效规范

- 组件状态：hover/active/focus/disabled 全站统一（按钮 primary 紫、focus ring 紫）；
- 动效：淡入上移、卡片悬浮、数字滚动；**禁用旋转/翻转/霓虹**等过时特效。

## 七、管理后台系统设计（新增）

### 7.1 定位

管理后台是**平台运营层**，区别于教学层（教师/学生）。管理员负责平台的组织、用户、课程、系统配置与数据运维，不参与具体教学，也不归属任何课程。

### 7.2 功能模块

| 模块 | 核心功能 |
|------|----------|
| **系统总览** | 平台数据仪表盘：用户数、课程数、作业数、AI 调用量、存储使用、活跃趋势 |
| **组织架构** | 学校 → 学院 → 专业 → 班级 树形 CRUD（这是 `school/college/major/class` 表的真正用武之地） |
| **用户管理** | 教师/学生/管理员账号：新增、角色分配、重置密码、启用/禁用、批量导入 |
| **课程管理** | 全部课程列表、课程状态（审核/下架）、课程统计（学生数/作业数） |
| **数据统计** | 平台使用数据、AI 调用量与成本、存储使用趋势 |
| **系统设置** | AI 模型配置（API Key/模型名）、通知设置、平台参数 |
| **日志审计** | 操作日志（`audit_log`）、登录日志 |
| **数据备份** | SQLite 单文件一键备份/恢复（下载备份文件） |

### 7.3 权限边界

- 管理员**不归属课程**、不参与教学（不批改、不答题）；
- 管理员可查看全平台数据（含所有课程/用户），但**不改学生成绩**（成绩是教学域数据，管理员只读）；
- 关键操作（改角色、禁用用户、改系统配置、备份恢复）写 `audit_log` 审计留痕。

### 7.4 数据模型补充

- `user.role` 扩展 `admin`；
- 新增 `audit_log`（操作日志：操作人/类型/对象/详情/时间）；
- 新增 `system_config`（系统配置 key-value，存 AI Key、模型名、平台参数）。

## 八、数据模型设计（SQLite 完整 DDL）

> 约定：主键 `INTEGER PRIMARY KEY AUTOINCREMENT`；布尔用 INTEGER(0/1)；时间用 TEXT(ISO8601)；JSON 用 TEXT 序列化；外键 `PRAGMA foreign_keys=ON`；WAL 模式 + busy_timeout。

### 8.1 表结构分组（23 张核心表 + 基础组织表）

| 分组 | 表 |
|------|-----|
| 权限 | `user`、`course` |
| 课程资源 | `learning_material`、`learning_behavior_log` |
| 图谱 | `knowledge_point`、`ability_point`、`ideology_point`、`ability_knowledge`、`ideology_knowledge` |
| 题目 | `question` |
| 作业 | `assignment`、`assignment_question` |
| 提交 | `answer`、`answer_item` |
| 批改 | `grading_task`、`review_record` |
| 错题 | `error_book`、`error_review` |
| 学情 | `knowledge_mastery_log`、`study_plan`、`study_session` |
| 通知 | `notification` |
| 答疑 | `qa_session`、`qa_message`（扩展功能，见第九节） |

> 基础组织表 `school/college/major/class` 沿用现有 23 表，此处不重复列出。

### 8.2 完整 DDL（SQLite）

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;

-- ============ 权限 / 组织 ============
CREATE TABLE user (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  real_name     TEXT NOT NULL,
  role          TEXT NOT NULL DEFAULT 'student',   -- teacher | student | admin
  student_level TEXT,                              -- top | medium | weak
  class_id      INTEGER REFERENCES class(id),
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE course (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  teacher_id  INTEGER NOT NULL REFERENCES user(id),
  class_id    INTEGER REFERENCES class(id),
  semester    TEXT,
  cover_color TEXT,                               -- 课程卡片渐变封面色（如 violet/fuchsia）
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ============ 图谱 ============
CREATE TABLE knowledge_point (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  course_id   INTEGER NOT NULL REFERENCES course(id),
  difficulty  INTEGER DEFAULT 1,
  parent_id   INTEGER REFERENCES knowledge_point(id)
);

CREATE TABLE ability_point (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  description TEXT,
  course_id   INTEGER NOT NULL REFERENCES course(id)
);

CREATE TABLE ideology_point (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  description TEXT,
  course_id   INTEGER NOT NULL REFERENCES course(id)
);

CREATE TABLE ability_knowledge (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  ability_id   INTEGER NOT NULL REFERENCES ability_point(id),
  knowledge_id INTEGER NOT NULL REFERENCES knowledge_point(id),
  weight       REAL DEFAULT 1,
  UNIQUE(ability_id, knowledge_id)
);

CREATE TABLE ideology_knowledge (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  ideology_id  INTEGER NOT NULL REFERENCES ideology_point(id),
  knowledge_id INTEGER NOT NULL REFERENCES knowledge_point(id),
  UNIQUE(ideology_id, knowledge_id)
);

-- ============ 课程资源 ============
CREATE TABLE learning_material (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id        INTEGER NOT NULL REFERENCES course(id),
  title            TEXT NOT NULL,
  type             TEXT NOT NULL,          -- video | courseware | doc
  url              TEXT NOT NULL,
  duration_seconds INTEGER,
  knowledge_ids    TEXT,                   -- JSON 数组
  created_at       TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

CREATE TABLE learning_behavior_log (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  student_id     INTEGER NOT NULL REFERENCES user(id),
  material_id    INTEGER NOT NULL REFERENCES learning_material(id),
  watch_duration INTEGER DEFAULT 0,
  progress       REAL DEFAULT 0,
  stay_time      INTEGER DEFAULT 0,
  replay_count   INTEGER DEFAULT 0,
  is_completed   INTEGER DEFAULT 0,
  viewed_at      TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ============ 题目 ============
CREATE TABLE question (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id      INTEGER NOT NULL REFERENCES course(id),
  content        TEXT NOT NULL,
  question_type  TEXT NOT NULL,            -- single/multi/judge/fill/short/code
  options        TEXT,                     -- JSON
  answer         TEXT NOT NULL,
  analysis       TEXT,
  difficulty     INTEGER DEFAULT 2,
  knowledge_id   INTEGER REFERENCES knowledge_point(id),
  created_by     INTEGER REFERENCES user(id),
  created_at     TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ============ 作业 ============
CREATE TABLE assignment (
  id                      INTEGER PRIMARY KEY AUTOINCREMENT,
  course_id               INTEGER NOT NULL REFERENCES course(id),
  title                   TEXT NOT NULL,
  description             TEXT,
  assignment_type         TEXT NOT NULL DEFAULT 'homework',
  status                  TEXT NOT NULL DEFAULT 'draft',
  review_mode             TEXT NOT NULL DEFAULT 'auto',   -- auto | teacher_review
  has_subjective          INTEGER NOT NULL DEFAULT 0,
  publish_time            TEXT,
  start_time              TEXT,
  due_time                TEXT,
  allow_late_submission   INTEGER NOT NULL DEFAULT 0,
  late_due_time           TEXT,
  time_limit_minutes      INTEGER DEFAULT 0,
  allow_resubmit          INTEGER NOT NULL DEFAULT 0,
  max_attempts            INTEGER NOT NULL DEFAULT 1,
```

### 8.4 并发与一致性（SQLite 落地关键）

WAL 模式（读不阻塞写）+ 写队列串行 + busy_timeout 5000ms + 事务（提交=answer+N条answer_item 原子）+ better-sqlite3 在线备份 API。

### 8.5 模型待澄清项

1. 附件/图片：`student_answer` 仅存 URL，文件落对象存储（本地 data/uploads）；
2. 客观题部分给分：`score_detail` 存 JSON 分步给分；
3. 批改归属去重：`review_record` 以 (grading_id, reviewer_id) 对齐，同一题不重复复核；
4. **题目跨课程复用**：`question.course_id` 归属课程，采用"课程内私有"，跨课需复制（学习通模式）。
