# 溯光 TracingLight · 批改系统强化方案

> 版本：v1.0　|　范围：填空题 / 客观题批改的「语义等价」判定强化
> 触发问题：学生作答「4分之1」、参考答案「0.25」，被判 0 分（数学等价但字符串不等）

---

## 一、问题定位

### 1.1 现象

| 题目 | 参考答案 | 学生作答 | 实际判分 | 期望判分 |
|------|----------|----------|----------|----------|
| Sigmoid 函数梯度最大值为____ | `0.25` | `4分之1` | 0 / 5 | 5 / 5（等价） |

### 1.2 根因

现有客观题规则引擎 `objective-grading.ts` 对填空题（`fill_blank`）只做：

```
去空白 → 转小写 → 去括号 → 字符串精确匹配
```

`4分之1` 与 `0.25` 归一化后仍是两个不同字符串 → 判 0 分。

**本质缺陷**：规则引擎只有「字面相等」判断，没有「数值等价 / 语义等价」判断。数学题答案存在大量等价表达（分数、小数、百分比、中文数字、科学计数法），单纯字符串匹配必然误伤。

### 1.3 影响范围

| 题型 | 等价表达示例（参考答案 `0.25`） |
|------|----------------------------------|
| 填空 | `1/4`、`4分之1`、`四分之一`、`25%`、`百分之二十五`、`0.250`、`1÷4` |
| 单选/判断 | 一般不受影响（选项字母精确匹配） |
| 多选 | 一般不受影响（选项字母集合匹配） |

---

## 二、强化方案：分层批改架构

核心思路：**「快规则优先，准 AI 兜底」三层判定**，让每道填空题都能得到正确判定，同时把 AI 调用量压到最低。

```
填空题判定链：
  ┌─ 第1层：文本精确匹配（去空白/小写/全半角/括号）—— 命中即满分
  ├─ 第2层：数值等价匹配（分数/小数/百分比/中文数字归一化）—— 命中即满分
  └─ 第3层：AI 语义判定（规则无法确定的开放答案）—— 升级提示词，等价即正确
```

| 层 | 判据 | 速度 | 成本 | 职责 |
|----|------|:---:|:---:|------|
| 1 文本精确 | 归一化字符串相等 | 极快 | 免费 | 代码/术语/字母等确定答案 |
| 2 数值等价 | 数学值相等（容差 1e-6） | 快 | 免费 | 分数/小数/百分比/中文数字 |
| 3 AI 语义 | 大模型判定等价性 | 慢 | 按量 | 开放文字答案、近义表述 |

**关键变更**：第 1、2 层都无法确定时，**不再直接判 0**，而是返回 `null` 交给 AI（第 3 层）做语义判定——避免「规则引擎不认识的等价表达被误杀」。

## 三、填空题数学等价判定规则（第 2 层）

### 3.1 归一化函数设计

新增 `parseMathValue(s)`：把各种数学表达解析为统一数值 `number`，解析失败返回 `null`。

```
输入            →  解析过程              →  数值
─────────────────────────────────────────────────────
0.25            →  直接 parseFloat         →  0.25
0.250           →  直接 parseFloat         →  0.25
.25             →  补 0 后 parseFloat       →  0.25
1/4             →  分子 1 ÷ 分母 4          →  0.25
4分之1          →  分子 1 ÷ 分母 4          →  0.25
四分之一         →  中文数字 1 ÷ 4          →  0.25
25%             →  25 ÷ 100               →  0.25
百分之25        →  25 ÷ 100               →  0.25
百分之二十五     →  中文数字 25 ÷ 100       →  0.25
1÷4             →  1 ÷ 4                  →  0.25
```

### 3.2 支持的模式

1. **百分比**：`X%`、`百分之X`（X 可为阿拉伯或中文数字）；
2. **分数**：`A/B`、`A／B`、`A÷B`、`X分之Y`（`X分之Y` = Y/X，中文习惯「4分之1」= 1/4）；
3. **小数/整数**：`-?\d+(\.\d+)?`，含 `.5` 这类省略整数位；
4. **中文数字**：0–99 的基本中文数字（含「十」「两」），如「四」「二十五」。

### 3.3 数值相等判定

```ts
function areNumericEqual(a: string, b: string): boolean {
  const va = parseMathValue(a);
  const vb = parseMathValue(b);
  if (va == null || vb == null) return false;
  return Math.abs(va - vb) < 1e-6;   // 浮点容差
}
```

## 四、AI 批改提示词升级（第 3 层）

### 4.1 新增判定规则

在 `GRADING_SYSTEM_PROMPT` 中新增「客观题 / 填空题等价判定」章节：

1. **数值等价即正确**：分数、小数、百分比、科学计数法、中文数字之间互相等价（`1/4` = `0.25` = `25%` = `四分之一`），一律判满分；
2. **表述形式差异不扣分**：全角/半角、大小写、多余空格、括号形式、数字格式（`0.25` vs `0.250`）不构成错误；
3. **单位一致时数值相等即正确**（如 `1000ms` 与 `1s` 在允许换算时视为等价，需题目上下文支持）；
4. **同义术语**：术语的常见同义/缩写（如 `深度学习` 与 `DL`、`卷积神经网络` 与 `CNN`）在填空题中视为等价；
5. **杜绝「形式误判」**：只有当语义确实错误、概念确实混淆时才扣分，绝不因「写法不同」扣分。

### 4.2 输出约束增强

- `total_score` 判定以「语义等价」为准，等价即满分；
- 等价时 `annotations` 可给出「等价表达」的说明性批注，但 `point_deduction` 必须为 0；
- `error_type` 仅在真错误时标记，等价作答不得标记 `wrong` / `calculation_error`。

## 七、遗留风险与后续

1. **中文数字解析覆盖有限**（0–99 基础数字），「一百二十五」「千分之三」等复杂表达暂不覆盖——超出范围会落到第 3 层 AI 兜底，不会误杀；
2. **单位换算**（`1000ms` vs `1s`）需结合题目上下文，规则引擎暂不做，交由 AI 判定；
3. 后续可扩展：科学计数法（`2.5e-1`）、根式（`√`）、复数、矩阵等，同样遵循「规则引擎能确定→规则引擎，否则 AI 兜底」的原则渐进增强。
