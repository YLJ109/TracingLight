# 作业/考试种子数据全面合理化整改方案 V3（企业级）

## 一、现状诊断（为什么是“糊弄”）

对 `seed/questions.ts` 逐段核查，确认当前题目完全是**模板拼接的假数据**，三处硬伤：

### 1. 题干模板化，题目本身不成题
所有题目都由形如 `关于「{知识点名}」，下列说法正确的是`、`请补全：……核心要点在于______`、`判断正误：……需要掌握` 的模板拼出来，**没有真正的考点与情境**。学生看到的就是一堆空泛套话。

### 2. 选项/答案假、选项相互不独立
单选/多选的四个选项统一是 `{知识点名}基础说明1/2/3/4`，肉眼可见是同一句话换个数字，**互斥性、干扰性完全缺失**；
判断题“核心要点需要在某章学习中掌握”毫无判断价值；填空答案直接等于知识点名。

### 3. 主观题有题无解、答非所问
简答/编程题的“参考答案”固定是 `1)概念界定;2)关键机制与流程;3)典型场景;4)注意事项`。
**纯理论论述框架，回答不了“编程实现异常与断言”这类要求**——这正是截图里“第8题·编程实现”却给出理论四个要点的根本原因。
加之组卷从同一道题库反复抽题，多份作业/考试重复刷同几道模板题，进一步放大了“糊弄感”。

### 4B. 分值显示不一致
批改页题头用 `question.default_score`（15分），而评分区用归一化后的 `grading.full_score`（18分），同一题出现“15分 / 12/18”两个满分口径，直接破坏公信力。

---

## 二、整改目标

1. **题目真实可用**：每题有明确题干、**相互独立且互斥**的正确/干扰选项、唯一标准答案、分步解析、对应{章节·知识点}。
2. **按章节知识组织**：题目严格隶属其知识点的真实考纲，不跨点、不串章；题目关系可溯到章节→知识点。
3. **全局不重复、独立性**：全文案题目唯一，同一试卷内不重题、同卷题型分值自洽；题库每题仅测一个知识点。
4. **答题/批改数据真实**：学生作答、错题归因、掌握度回写与题目内容一致；分数口径统一为满分 100。

---

## 三、整改方案

### A. 题目库重构（核心）
放弃模板生成，改为**手写真实题目内容**，按 `课程 → 章节 → 知识点` 建库：

| 层级 | 现状 | 整改后 |
|---|---|---|
| 题干 | 模板字符串 | 真实考点 + 情境（补全/判断/场景/算法演示等） |
| 选项 | `{名}{编号}` 假选项 | 独立互斥的正确/干扰项，干扰项贴合真实易错点 |
| 答案 | 模板/知识点名 | 唯一且严谨的标答 |
| 解析 | `考察{知识点}` 一句话 | 分步推导 + 错误项逐项点破 + 学情建议 |
| 题型分布 | 每课 6 类 ×10 | 按知识点属性分配（判断/选择/填空/简答/编程） |
| 题量 | 每课 60 模板题 | 每知识点手写 2~3 道真题，**全库去重** |

> 型号库样例（Python·第3章·异常与断言）：
> - 判断：`Python 中 except 语句可以同时捕获多个异常类型（如 except (TypeError, ValueError)），且捕获顺序无关紧要。` 对 `错`（解析：顺序有关，先匹配先执行）。
> - 单选：`以下哪种写法能在除零前优雅退出而不中断程序？ A. assert x!=0  B. try/except ZeroDivisionError  C. pass  D. raise ValueError` 答案 B
> - 编程：`编写函数 safe_div(a,b)，用 try/except 捕获 ZeroDivisionError 返回 None，并在 b==0 时用 assert 拦截并给出中文提示。` 附完整代码+注释答案。

### B. 组卷策略（去重 + 覆盖合理）
- 每份作业/考试按**章内随机、章间均衡**抽题，保证覆盖多个章节；
- 同一卷内题目绝不重复；卷与卷之间允许少量复用但**避免同一模板连续出现**；
- 主观题（简答/编程）每卷至少 1 道，且与客观题考点错开，防止“同一知识点既选择又编程”造成掌握度污染。

### C. 分值口径统一（修 Bug）
- 批改页题头 `({q.default_score}分)` 改为显示当前题的实际满分 `full_score`，消除“15分 vs 18分”；
- 保留 `normalizeScores` 归一到 100 的机制，确保作业/考试满分恒为 100，且题头与评分区一致。

### D. 真实作答数据
- 学生作答按真实正确率与分层生成，主观题作答内容与题目匹配（非“作答要点不全”占位）；
- 错题归因、掌握度回写基于真实判分，口径与 `grading.service` 统一。

---

## 四、工作量与影响

- 手写题目总量：4 门课 × 20 知识点 × 2~3 题 ≈ **160~240 道真实题目**（含完整选项、答案、解析）。
- 仅改数据种子与 1 处分值显示；不改接口契约、不改页面结构，回归风险低。
- 生效方式：删除 `data\racinglight.db` → 重跑 `setup.bat`（或 `start.bat dev`）重建。

## 五、需要你拍板的 3 个决策

1. **题量口径**：每题 2 道（更稳、工作量小）还是 3 道/知识点（更丰富）？
2. **编程/简答参考答案**：是否允许携带**真实可运行代码**（提升真实感，文件更大）？
3. **生效范围**：4 门课全部重写，还是先只重写截图对应的 Python 课验收？
