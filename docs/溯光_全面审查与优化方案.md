# 溯光 TracingLight — 全面审查与优化方案

> 审查对象：学生端 / 教师端 / 管理后台全功能 + 工程质量与安全
> 基准：对照 学习通(超星泛雅) / 智慧树 等主流高校教育软件的交互细节与功能闭环
> 日期：2026-09-05

---

## 一、审查执行摘要

| 维度 | 结论 |
|---|---|
| 鉴权/越权基线 | 良好。统一 requireAuth + 归属校验 + token_version 撤销 + 登录限流 + 富文本 XSS 白名单清洗 |
| 成绩发布闭环 | 已打通（一键发布成绩，发布前学生隐藏分数） |
| 主要遗留工程债 | ESLint 存量约 200 处 no-explicit-any；JWT/会话存 localStorage；sql.js 退出落盘 |
| 与学习通差距 | 缺：文件/拍照/云盘提交、补考重发、测试卷、查重、字数限制、讨论区、通知中心、材料阅读时长、成绩导出、移动端 H5 |

## 二、问题清单（编号 · 含严重度）

### A. 前端交互与细节问题（现存）

| # | 严重度 | 模块·问题 | 位置 | 表现 / 建议 |
|---|---|---|---|---|
| A1 | 高 | 学生作答富文本曾显示原始 HTML（不渲染） | teacher grade/page.tsx:394 | 已修复（span+white-space:pre 识别） |
| A2 | 中 | 编辑区曾白字/白底视觉冲突 | rich-answer.tsx / globals.css | 已修复（背景分层+强制黑+保存清洗） |
| A3 | 中 | 教师新建作业前端仍携带 `teacher_id:1` | teacher/assignments/new/page.tsx | 后端已用 token 覆盖，应从前端**移除**该字段，避免误导/卫生风险 |
| A4 | 中 | 多个页面缺统一空态/加载态/错误态 | 各列表页 | 对照学习通，空列表应有引导插图+文案+行动按钮；请求失败应有重试 |
| A5 | 中 | 危险操作（删除/退回/发布/重置）二次确认不统一 | 各页面 | 删除类应二次确认；退回/发布前应提示影响范围 |
| A6 | 低 | 提交按钮双击防抖不统一 | assignments 提交 | 建议统一 `submitting` 状态禁用，避免重复提交 |
| A7 | 低 | 移动端响应式支持不足 | 全局 | 学习通有完整 H5/APP，本项目桌面为主；建议至少保证关键流程窄屏可用 |

### B. 后端 / 数据 / 安全（现存 + 建议）

| # | 严重度 | 模块·问题 | 位置 | 表现 / 建议 |
|---|---|---|---|---|
| B1 | 中 | JWT 与用户会话存 localStorage | app/page.tsx / lib/api-fetch / lib/auth-helper | 存在 XSS 窃取风险；建议改 httpOnly cookie（已设 sb-auth cookie 作 proxy 辅助，可推广） |
| B2 | 中 | sql.js 内存库 + 30s 落盘 | storage/database/db.ts:209+ | 并发写与崩溃窗口；生产建议迁移 better-sqlite3 文件库 |
| B3 | 中 | ESLint 配置历史问题 + 存量 ~200 处 no-explicit-any | eslint.config.mjs / 全库 | 建议专项收口类型，恢复 lint 门禁 |
| B4 | 低 | 各写接口 saveDb 覆盖一致性 | 各 route | 已补 behavior/schedule/签到/发布等；建议统一封装“写后落盘”以便全程覆盖 |
| B5 | 低 | 富文本渲染依赖 dangerouslySetInnerHTML + sanitize | rich-content.tsx | 依赖上游清洗；建议对 admin/teacher 公告等输入再做二次白名单校验落库 |

### C. 功能流程闭环差距（对照学习通）

| # | 模块·差距 | 建议 |
|---|---|---|
| C1 | 作业提交方式 | 现仅在线富文本。建议支持**文件上传 / 拍照 / 附件多类型**（学习通支持 docx/pdf/图片、单文件≤100MB） |
| C2 | 打回重做 | 已支持退回重做；建议退回理由必填 + 学生端醒目横幅+截止时间 |
| C3 | 成绩发布 | 已打通手动发布；建议**全客观题 48h 自动发布 + 主观题手动发布**（参照智慧树）并行，教师可切换 |
| C4 | 客观/主观阅卷状态 | 学习通：客观自动、主观师阅。本项目 review_mode 已有，建议教师端按状态清晰区分“待阅/已阅/已发布” |
| C5 | 重复提交策略 | 建议设置中体现“允许重新提交”，学生可见“修改提交”入口与截止时间 |
| C6 | 作业/考试时间窗 | 建议超时自动关闭提交并提示，支持教师补考/重新发放 |
| C7 | 通知中心 | 建议新增按“作业发布/被退回/成绩发布/AI批改完成”的通知+红点，替代纯订阅通知 |
| C8 | 错题/练习闭环 | 已有关联；建议练习掌握度回写知识图谱并同步提示 |
| C9 | 学习进度 | 材料“秒完成”问题应计真实阅读时长；章节任务点/必学标记可参考 |
| C10 | 讨论区 | 学习通核心模块，本项目无。可作为后续加分项（发帖/回复/点赞/权重计分） |

### D. 新增功能建议（对照基准，优先级高→低）

1. **D1（高）** 成绩/作答**批量导出**（未交名单、成绩、单题作答详情 → excel）
2. **D2（高）** 题库增强：题目**正确率**统计、批量设难度/关联知识点、锁定题目、使用量、随机组卷
3. **D3（中）** 简答题**字数限制**（最少/最多，不满足不可提交）
4. **D4（中）** 测评题：选项可独立设分、限制选择数量
5. **D5（中）** 签到/讨论引入**权重制**（签到率、讨论贡献计平时分）
6. **D6（低）** 材料阅读时长统计 + 学习监控统计看板
7. **D7（低）** 课程门户/章节内知识点定位、边看边笔记

## 四、分阶段优化路线图

### P0 优先修复（影响数据/安全/核心可用）
1. 移除教师新建作业前端 `teacher_id:1` 冗余传参（A3）
2. 会话/JWT 从 localStorage 迁移到 httpOnly cookie（B1）
3. 写接口落盘统一封装，补齐漏 saveDb（B4 + 已处理项复核）
4. 富文本/公告等所有人输入再落库前二次清洗（B5）

### P1 体验完整（接近学习通可用度）
5. 全局统一空态/加载/错误态组件（A4）、危险操作二次确认规范（A5）、提交防抖（A6）、移动端关键路径适配（A7）

7. 通知中心 + 红点（C7）
8. 成绩导出 + 未交名单（D1）

10. 全客观自动发布 + 主css观手动发布可切换（C3）

### P2 增强
